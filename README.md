# مناقشة بروجكت AI — موقع جدولة المناقشات

موقع بسيط بيسمح لكل الطلبة إنهم:
- يسجلوا فريق جديد (حتى 3 أفراد) لو لسه مسجلوش.
- يختاروا يوم المناقشة (الأربعاء أو الخميس) — واليوم بيتقفل تلقائيًا لما يوصل لنص عدد الفرق كلها.
- يشوفوا الجدول الكامل بالمواعيد (كل فريق 5 دقايق).

الموقع static بالكامل (HTML/CSS/JS) وشغال على GitHub Pages من غير أي تسجيل دخول للزوار.
لكن عشان كل الناس تشوف نفس البيانات لحظيًا (مش كل واحد شايف نسخته بس)، الموقع بيستخدم
**Firebase Realtime Database** كقاعدة بيانات مجانية بدون تسجيل دخول للمستخدمين.

> **ملاحظة مهمة:** GitHub Pages بيستضيف ملفات ثابتة بس، مفيش سيرفر/باك إند. علشان
> كل الطلبة يقدروا يعدلوا نفس القاعدة بدون تسجيل دخول، لازم قاعدة بيانات خارجية مفتوحة
> زي Firebase. الخطوات دي تتعمل **مرة واحدة بس من صاحب المشروع** (مش من كل طالب).

---

## 1) اعمل مشروع Firebase مجاني (5 دقايق)

1. روح على https://console.firebase.google.com وسجل دخول بحساب جوجل بتاعك.
2. دوس **Add project** واختار اسم زي `ai-project-discussion` ثم كمّل الخطوات (تقدر توقف Google Analytics).
3. من القائمة الجانبية: **Build > Realtime Database > Create Database**.
   - اختار أي location قريب.
   - اختار **Start in test mode** (ده هيخليها متاحة قراءة/كتابة لمدة 30 يوم افتراضيًا).
4. بعد ما تتعمل، روح لتبويب **Rules** فوق، وامسح اللي موجود وحط بدله:

   ```json
   {
     "rules": {
       ".read": true,
       ".write": true
     }
   }
   ```

   دوس **Publish**. (ده هيخلي القاعدة مفتوحة للكل بدون تسجيل دخول، زي المطلوب بالظبط.
   خليها كده لحد ما تنتهي المناقشات، وبعدين تقدر تقفلها أو تمسح المشروع.)

5. من القائمة الجانبية: **Project settings** (الترس بجانب Project Overview) > انزل لـ **Your apps**
   > دوس أيقونة الويب `</>` > سمّي التطبيق أي اسم > **Register app**.
6. هيديك object اسمه `firebaseConfig` فيه قيم زي `apiKey`, `databaseURL`, إلخ. **انسخهم**.

---

## 2) حط بياناتك في المشروع

افتح ملف `firebase-config.js` واستبدل القيم بالقيم اللي نسختها من Firebase:

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  databaseURL: "https://....firebaseio.com",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

مهم جدًا: قيمة `databaseURL` لازم تكون موجودة (هي أهم قيمة عشان الموقع يشتغل).

---

## 3) ارفع المشروع على GitHub Pages

1. اعمل مستودع (repository) جديد على GitHub، وارفع كل الملفات دي (`index.html`, `style.css`,
   `app.js`, `firebase-config.js`, `seed-data.js`, `README.md`) في الجذر (root) بتاعه.
2. روح لإعدادات المستودع **Settings > Pages**.
3. تحت **Build and deployment**، اختار **Deploy from a branch**، وفي Branch اختار
   `main` والمجلد `/ (root)`، ثم **Save**.
4. GitHub هيديك رابط زي:
   `https://USERNAME.github.io/REPO-NAME/`
   استنى دقيقة أو اتنين وافتحه.

كده الموقع شغال، وأي حد يفتح الرابط يقدر يسجل فريق أو يختار يومه بدون أي تسجيل دخول،
وكل التعديلات بتتحدث لحظيًا لكل الزوار.

---

## ملاحظات على المنطق

- **بيانات الفرق الموجودة مسبقًا** (61 فريق من ملف الإكسل) بتتحمّل تلقائيًا في أول مرة
  حد يفتح فيها الموقع لو قاعدة البيانات فاضية (من ملف `seed-data.js`). مش محتاج تعمل حاجة يدوي.
- **رقم الفريق الجديد** بيتحدد تلقائيًا = أكبر رقم فريق موجود + 1.
- **سعة كل يوم** = نص العدد الكلي للفرق المسجلة (لو العدد فردي، الأربعاء بياخد الفريق الزيادة).
  السعة بتتحدث تلقائيًا كل ما فريق جديد يتسجل.
- **مفيش فريق يقدر يختار يومه مرتين** — بمجرد ما يختار، الأزرار بتتقفل له.
- **جدول المواعيد** بيتحسب تلقائيًا: الأربعاء يبدأ 10:00، الخميس يبدأ 11:30، وكل فريق ياخد
  5 دقايق بالترتيب اللي اختار بيه يومه.

## تشغيل محلي للتجربة

تقدر تفتح `index.html` مباشرة في المتصفح بعد ما تحط بيانات Firebase بتاعتك — مش محتاج سيرفر.
